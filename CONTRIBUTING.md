# Contributing to QuickPeek

Thanks for helping. QuickPeek fills gaps in macOS Quick Look with Apple's own frameworks; a change should keep it small, native and free of settings.

## Principles

- **Apple frameworks first.** VideoToolbox, AudioToolbox, TextKit, JavaScriptCore, ImageIO, the system libarchive. No bundled ffmpeg or other large libraries.
- **Only fill gaps.** If macOS already previews a format well, leave it to the system.
- **No settings UI.** Sensible defaults; extensions are switched on and off in System Settings.
- **Tests first.** Parsers and readers are covered by `swift test`, against real files where possible.

## Setup

Requires macOS 26 and Xcode 26.

```sh
brew install xcodegen
script/build.sh      # swift test, then a Release build in build/QuickPeek.app
script/install.sh    # install to /Applications and enable the extensions
```

`project.yml` is the source of the Xcode project; `QuickPeek.xcodeproj` is generated and not committed.

## Layout

```
Sources/QuickPeekCore     file classification, text decoding, CSV parsing
Sources/QuickPeekText     highlight.js in JavaScriptCore, Markdown renderer, document views
Sources/QuickPeekMedia    Matroska/WebM demuxer, CoreMedia bridge, frame extraction, player
Sources/QuickPeekFormats  archives (system libarchive), torrents, app packages (IPA, APK)
Sources/QuickPeekInfo     file details engine and the Finder menu
Sources/CArchive          declarations for the system libarchive (the SDK has no header)
PreviewExtension          Quick Look preview extension
ThumbnailExtension        Finder thumbnails (video keyframes, app icons)
FinderSyncExtension       the file-details context menu
App                       host app and debugging command line
Tests                     swift test; fixtures and their generator scripts
Vendor                    highlight.js, pinned by SHA-256
Resources                 app icon source (SVG)
```

All `Sources/` modules ship as one framework, `QuickPeekKit`, embedded once in the app.

## Debugging without Finder

The app doubles as a command-line tool that runs the same code as the extensions:

```sh
QP=build/QuickPeek.app/Contents/MacOS/QuickPeek
$QP --snapshot file out.png [--dark]   # a document, archive, torrent or app preview as a PNG
$QP --play movie.mkv                   # the Quick Look player in a window
$QP --play-snapshot movie.mkv out.png  # play briefly and save the player as a PNG
$QP --thumbnail movie.mkv out.png      # the Finder thumbnail frame
$QP --probe movie.mkv                  # tracks and frame counts, like ffprobe
$QP --info [--quick] file…             # file details, like mediainfo
$QP --snapshot-info file out.png       # the ⓘ panel as a PNG
$QP --package app.apk                  # app package fields as JSON
```

`qlmanage -p` does not exercise app extensions; use the commands above, or Finder.

## Tests and fixtures

```sh
swift test
```

Fixtures are small and generated by scripts, so they can be rebuilt:

- `script/make_fixtures.sh` — media files (needs ffmpeg, a development tool only)
- `script/make_format_fixtures.py` — torrents and Office documents
- `script/make_archive_fixtures.sh` — archives; RAR and 7z samples come from libarchive's tests
- `script/make_app_fixtures.sh` — an IPA and an Xcode archive with a provisioning profile

Larger conformance checks run against public test suites kept out of the repository: the official Matroska test files (frame counts match ffprobe) and androguard's APKs (fields match androguard).

CI runs on GitHub's macOS VMs, which have no hardware video decoder or audio device; the two player checks that need them run only on a real Mac with an unlocked screen.

## Other scripts

- `script/generate_icon.sh` — the app icon set from `Resources/AppIcon.svg`
- `script/fetch_vendor.sh` — update highlight.js (`--update-checksums` after changing the version)

## Releases

1. Set `MARKETING_VERSION` in `project.yml` and add a `## X.Y.Z — date` section to `CHANGELOG.md`.
2. Push a tag: `git tag vX.Y.Z && git push origin vX.Y.Z`.

The release workflow checks that the version, tag and changelog agree, builds the app, attaches `QuickPeek-X.Y.Z.zip` to a GitHub release, and points the Homebrew cask in [yinon-mitin/homebrew-tap](https://github.com/yinon-mitin/homebrew-tap) at it (using the `TAP_TOKEN` secret). To re-point the cask at an existing release, run the workflow by hand from the Actions tab with that tag.
